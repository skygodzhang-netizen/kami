## 1. 概览与设计理念

### 1.1 核心定位

错误智慧库是记录层的**第三轨存储**，专门用于记录、分析和复用错误经验，实现"从错误中学习"的智能体进化能力。

### 1.2 核心价值

- **避免重复犯错**：从历史错误中提取预防知识
- **加速学习曲线**：新错误立即转化为可复用知识
- **提升鲁棒性**：前置预防机制降低错误发生率
- **支持进化**：错误知识随时间积累和优化

### 1.3 设计原则

1. **超然性**：作为记录层的一部分，不主动干预主循环
2. **查询驱动**：由数学顶点/感知节点主动查询，而非被动推送
3. **渐进式披露**：工具性错误优先（规则明确），认知性错误后续扩展
4. **时效性**：错误知识具有生命周期，过期自动降权或清理

### 1.4 从"纠错"到"预防"的进化

```
现有机制（事后纠错）：
用户输入 → 推理 → 错误 → 检测 → 纠错 → 输出

错误智慧库（事前预防）：
用户输入 → 查询预防知识 → 调整策略 → 推理 → 输出
                          ↓
                    （更少错误）
```

### 1.5 错误学习的闭环

```
发现问题 → 分析原因 → 解决问题 → 形成预防知识 → 避免重复犯错
    ↑                                                        ↓
    └────────────── 验证与优化 ←─────────────────────────────┘
```

## 2. 核心概念与数据结构

### 2.1 错误智慧条目 (Error Wisdom Entry)

错误智慧库的基本单元，记录一次完整的错误学习经验。

**核心组成**：
- **错误发现**：发生了什么错误
- **原因分析**：为什么犯错
- **解决方案**：如何解决
- **预防知识**：下次如何避免
- **验证历史**：预防效果追踪

### 2.2 预防规则 (Prevention Rule)

从错误智慧条目中提取的可执行规则，用于前置检查。

**特征**：
- 可程序化执行
- 有明确的触发条件
- 有明确的预防动作

### 2.3 时效性 (Timeliness)

错误知识的有效性随时间衰减。

**三重衰减机制**：
1. **时间衰减**：自然过期
2. **场景变化衰减**：环境变化导致失效
3. **反例衰减**：遇到反例时重新评估

### 2.5 字段说明

| 字段路径 | 类型 | 必需 | 说明 |
|---------|------|------|------|
| id | string | 是 | 唯一标识，格式：ew_YYYYMMDD_序号 |
| timestamp | string | 是 | ISO 8601 时间戳 |
| trace_id | string | 是 | 关联的全链路追踪ID |
| version | string | 是 | 数据结构版本 |
| 错误发现.错误类型 | string | 是 | 工具性错误/认知性错误 |
| 错误发现.子类型 | string | 是 | 细分错误类型 |
| 错误发现.错误码 | string | 否 | 系统错误码 |
| 错误发现.严重程度 | string | 是 | none/mild/moderate/severe/critical |
| 原因分析.根本原因 | string | 是 | 核心原因描述 |
| 原因分析.可预防性 | string | 是 | high/medium/low |
| 预防知识.预防策略 | string | 是 | 预防方法描述 |
| 预防知识.前置检查规则 | object | 否 | 可程序化的预防规则 |

| 元数据.置信度 | float | 是 | 0.0-1.0，表示有效性 |
| 元数据.时效性标记 | string | 是 | active/deprecated/archived |

## 3. 错误分类体系

### 3.1 一级分类

```
错误智慧库
├─ 工具性错误（Phase 1 重点）
│  ├─ 调用失败类
│  ├─ 参数构造类
│  ├─ 结果处理类
│  └─ 工具选择类
│
└─ 认知性错误（Phase 2 扩展）
   ├─ 幻觉倾向类
   ├─ 推理跳跃类
   ├─ 知识缺失类
   └─ 偏见影响类
```

### 3.2 二级分类详解

#### 工具性错误

| 子类型 | 常见场景 | 典型错误码 | 预防价值 |
|--------|---------|-----------|---------|
| **调用失败类** | 网络超时、权限拒绝、资源不存在 | TIMEOUT, 401, 403, 404, 429 | 高（可重试/降级） |
| **参数构造类** | 格式错误、缺少参数、值非法 | INVALID_FORMAT, MISSING_PARAM, INVALID_VALUE | 极高（前置检查） |
| **结果处理类** | 解析失败、类型转换错误 | PARSE_ERROR, TYPE_ERROR | 高（增加容错） |
| **工具选择类** | 选错工具、组合顺序错误 | - | 中（需推理优化） |

#### 认知性错误

| 子类型 | 常见场景 | 检测方法 | 预防价值 |
|--------|---------|---------|---------|
| **幻觉倾向类** | 编造事实、虚构API | 元认知检测 | 中高 |
| **推理跳跃类** | 遗漏前提、逻辑跳跃 | 客观性评估 | 中 |
| **知识缺失类** | 知识库中没有相关信息 | 自我评估 | 中 |
| **偏见影响类** | 刻板印象、选择性注意 | 偏见检测 | 中低 |

## 5. Phase 2：认知性错误详解

### 5.1 概述

Phase 2 扩展错误智慧库以支持认知性错误的识别、分析和预防。认知性错误源于模型内部推理过程，包括幻觉倾向、推理跳跃、知识缺失和偏见影响四类。**详细定义与检测规则见第6章**。

### 5.2 认知性错误分类

#### 1. 幻觉倾向类（Hallucination）
**特征**：生成与事实不符或虚构的内容
**典型场景**：编造不存在的API或函数、虚构统计数据、生成不存在的引用
**检测方法**：元认知检测中的"幻觉检测模式"、客观性评估器的主观性维度检测、知识库交叉验证

#### 2. 推理跳跃类（Reasoning Jump）
**特征**：推理过程中遗漏关键前提或逻辑步骤
**典型场景**：直接给出结论而缺少论证、隐含假设未明确说明、因果关系过度简化
**检测方法**：客观性评估器的逻辑完整性检测、推理链路验证

#### 3. 知识缺失类（Knowledge Gap）
**特征**：知识库中缺少必要信息导致的错误
**典型场景**：回答超出知识截止日期的问题、领域专业知识不足、最新事件未更新
**检测方法**：自我评估机制、置信度阈值检测

#### 4. 偏见影响类（Bias Influence）
**特征**：刻板印象或选择性注意导致的偏见输出
**典型场景**：性别/地域/职业刻板印象、选择性引用信息、确认偏误
**检测方法**：偏见检测模式、多角度平衡性检查

## 6. 认知性错误定义与分类体系（详细版）

### 6.1 定义与目的

**定义**：认知性错误（Cognitive Errors）指智能体在认知过程中产生的系统性偏差或错误，区别于工具调用失败等技术性错误。认知性错误源于思维过程中的缺陷，而非外部环境或技术限制。

**目的**：
- **自我监控**：实现智能体的自我错误识别与纠正
- **持续改进**：通过错误学习提升认知能力
- **透明度提升**：记录并展示认知过程的局限性
- **用户信任**：主动承认错误，增强可信度

**与工具性错误的区别**：

| 维度 | 认知性错误 | 工具性错误 |
|------|-----------|-----------|
| 产生原因 | 内部认知缺陷 | 外部环境/技术限制 |
| 检测方式 | 自我反思/模式匹配 | 异常捕获/返回值检查 |
| 纠正机制 | 调整认知策略 | 重试/更换工具 |
| 记录重点 | 思考过程/根因 | 调用参数/失败原因 |
| 预防策略 | 提升认知能力 | 优化工具使用 |

### 6.2 四种认知性错误类型

#### 1. 幻觉倾向（Hallucination Tendency）

**定义**：生成看似合理但与事实不符或无法验证的陈述，通常表现为对不存在知识的编造或夸大。

**典型表现**：
- 声称知道实际上不存在的事实
- 提供无法验证的细节（如具体日期、人名、数据）
- 对模糊问题给出过度确定的回答
- 编造来源或引用不存在的文献

**识别场景**：
- 用户询问具体事实细节（如"2023年XX事件的具体时间"）
- 涉及冷门领域知识的查询
- 需要精确数据或引用的场景
- 用户要求提供证据或来源时

**检测关键点**：
- 回答中是否包含无法验证的具体细节
- 是否存在过度确定的表达（如"肯定是"、"绝对是"）
- 是否在缺乏信息的情况下编造答案
- 是否出现虚构的引用或来源

#### 2. 推理跳跃（Reasoning Leap）

**定义**：在推理过程中跳过必要的中间步骤，直接得出结论，导致逻辑链条不完整或因果倒置。

**典型表现**：
- 直接给出结论，省略推理过程
- 前提与结论之间的逻辑连接缺失
- 使用未经证实的假设作为推理基础
- 忽略重要的约束条件或边界情况

**识别场景**：
- 复杂的多步推理问题
- 需要严密逻辑推导的场景
- 涉及因果关系的分析
- 用户询问"为什么"或"如何"时

**检测关键点**：
- 回答是否提供完整的推理链条
- 结论是否有充分的前提支持
- 是否存在未明示的假设
- 是否忽略了重要的约束条件

#### 3. 知识缺失（Knowledge Gap）

**定义**：在缺乏足够知识的情况下，尝试通过合理化编造来掩盖无知，而不是明确承认不知道。

**典型表现**：
- 对不了解的主题给出似是而非的回答
- 用通用模板回答需要专业知识的问题
- 混淆相关但不完全适用的知识
- 回避明确承认知识边界

**识别场景**：
- 超出训练数据范围的新兴领域
- 需要最新信息的专业领域
- 小众或罕见的知识点
- 用户追问细节时

**检测关键点**：
- 回答是否缺乏具体深度
- 是否使用模糊的通用描述
- 是否在无法提供细节时强行补充
- 是否明确承认知识边界

#### 4. 偏见影响（Bias Influence）

**定义**：在回答中受到训练数据或先验偏见的系统性影响，导致判断不客观或带有倾向性。

**典型表现**：
- 对某些群体或观点持系统性偏向
- 在价值判断中缺乏中立性
- 无意识反映训练数据的偏见
- 在敏感话题上立场失衡

**识别场景**：
- 涉及价值观、伦理道德的问题
- 对不同群体进行比较或评价
- 处理争议性话题
- 用户要求中立分析时

**检测关键点**：
- 回答是否保持价值中立
- 是否平衡呈现多方观点
- 是否存在系统性偏向
- 在敏感话题上是否立场失衡

### 6.3 检测规则与判定标准

#### 通用检测框架

每个认知性错误类型通过以下维度进行判定：

1. **上下文分析**：问题类型与复杂度、信息充足度、预期回答质量标准
2. **模式匹配**：特定错误类型的语言模式、逻辑结构的异常模式、知识断言的可验证性模式
3. **一致性检查**：前后逻辑一致性、知识库一致性、上下文语义一致性
4. **置信度评估**：检测结果的确定性程度、边界情况的处理、不确定性标记

#### 幻觉倾向检测规则

| 检测维度 | 规则 | 判定标准 | 置信度 |
|---------|------|---------|-------|
| 具体细节检测 | 识别无法验证的具体事实（日期、姓名、数据） | 包含≥3个无法验证的具体细节 | 高 |
| 来源验证 | 检查是否声称有来源但无法提供 | 声称有来源但引用格式模糊或不存在 | 高 |
| 确定性表达 | 识别过度确定的语气词（"肯定是"、"绝对是"） | 在缺乏信息时使用≥2个确定性表达 | 中 |
| 可证伪性 | 评估陈述是否可被证伪 | 包含无法证伪的绝对化断言 | 中 |
| 模糊性分析 | 分析回答是否在关键信息上模糊 | 关键事实部分使用模糊词汇（"可能"、"大约"） | 低 |

#### 推理跳跃检测规则

| 检测维度 | 规则 | 判定标准 | 置信度 |
|---------|------|---------|-------|
| 步骤完整性 | 检查是否提供完整的推理步骤 | 结论前缺少≥1个必要的中间步骤 | 高 |
| 逻辑连接 | 评估前提与结论之间的逻辑连接 | 使用"因此"、"所以"但逻辑连接不成立 | 高 |
| 假设检查 | 识别未明示的假设 | 推理中包含≥1个未说明的隐含假设 | 中 |
| 约束忽略 | 检查是否忽略重要约束条件 | 忽略≥1个明确的前提约束 | 中 |
| 因果倒置 | 识别因果关系的倒置 | 将结果当作原因或混淆因果关系 | 高 |

#### 知识缺失检测规则

| 检测维度 | 规则 | 判定标准 | 置信度 |
|---------|------|---------|-------|
| 深度评估 | 评估回答的专业深度 | 对专业问题的回答停留在通用层面 | 中 |
| 模糊性分析 | 检查是否使用模糊语言回避细节 | 关键细节部分使用模糊词汇占比≥30% | 中 |
| 承认边界 | 检查是否明确承认知识边界 | 在涉及专业知识时未承认知识限制 | 低 |
| 细节回避 | 检查是否在追问细节时回避 | 追问细节后仍无法提供具体信息 | 高 |
| 通用模板 | 识别是否使用通用回答模板 | 回答结构与通用模板高度相似 | 中 |

#### 偏见影响检测规则

| 检测维度 | 规则 | 判定标准 | 置信度 |
|---------|------|---------|-------|
| 中立性评估 | 评估回答的价值中立性 | 在价值判断中明显偏向一方 | 高 |
| 观点平衡 | 检查是否平衡呈现多方观点 | 对争议话题仅呈现单一观点 | 高 |
| 群体偏向 | 识别对特定群体的偏向 | 在比较评价中系统性偏向某一群体 | 中 |
| 敏感话题 | 检查敏感话题的立场平衡 | 在敏感话题上立场失衡或回避 | 中 |
| 语言模式 | 识别带有倾向性的语言模式 | 使用带有情感色彩或评价性的词汇 | 低 |

### 6.4 严重性分级

#### 分级标准

**轻度（Low Severity）**
- **特征**：错误影响有限，不会误导用户，容易被识别
- **判定**：置信度≤50%的检测结果，或错误类型为知识缺失/偏见影响且影响范围小
- **处理**：记录并提示改进，不强制纠正

**中度（Medium Severity）**
- **特征**：错误可能影响用户决策或理解，需要引起注意
- **判定**：50%<置信度≤80%的检测结果，或错误类型为推理跳跃
- **处理**：记录并给出纠正建议，建议重新检查

**重度（High Severity）**
- **特征**：错误严重误导用户，可能导致错误决策或理解
- **判定**：置信度>80%的检测结果，或错误类型为幻觉倾向
- **处理**：立即纠正，明确承认错误，提供正确信息或说明

#### 严重性调整因子

| 因子 | 影响 | 调整幅度 |
|-----|------|---------|
| 用户专业度 | 用户是领域专家 | 严重性+1级 |
| 问题敏感性 | 问题涉及关键决策 | 严重性+1级 |
| 可验证性 | 回答内容可被用户验证 | 严重性-1级 |
| 上下文明确性 | 问题上下文非常明确 | 严重性-1级 |

### 6.5 根因分析框架

#### 分析维度

**1. 认知机制（Cognitive Mechanism）**
- 定义：导致错误的认知过程或思维模式
- 类型：信息不足时的填充机制、模式匹配的过度泛化、注意力分配不当、工作记忆限制
- 分析方法：基于错误类型和检测模式推断认知机制

**2. 知识边界（Knowledge Boundary）**
- 定义：错误发生的知识范围或领域
- 类型：时间边界（超出训练数据时间范围）、领域边界、细节边界、上下文边界
- 分析方法：分析问题涉及的知识域与训练数据覆盖

**3. 策略缺陷（Strategy Deficiency）**
- 定义：导致错误的行为策略或决策模式
- 类型：过度优化回答完整性、缺乏不确定性表达、优先考虑回答而非准确、忽略验证机制
- 分析方法：分析回答生成过程中的决策点

#### 根因分析流程

1. **错误模式识别**：从检测模式中提取关键特征
2. **认知机制推断**：基于错误类型推断可能的认知机制
3. **知识边界定位**：分析问题涉及的知识域
4. **策略缺陷分析**：识别导致错误的策略选择
5. **根因综合**：整合各维度分析，确定主要根因

#### 根因示例

| 错误类型 | 主要根因 | 次要根因 | 认知机制 |
|---------|---------|---------|---------|
| 幻觉倾向 | 知识边界模糊 | 缺乏验证机制 | 信息不足时的填充机制 |
| 推理跳跃 | 优化表达简洁性 | 忽略逻辑完整性 | 注意力分配不当 |
| 知识缺失 | 专业领域知识不足 | 缺乏诚实表达策略 | 模式匹配的过度泛化 |
| 偏见影响 | 训练数据偏见 | 缺乏中立性意识 | 隐式模式激活 |

### 6.6 预防建议生成策略

#### 建议分类

**1. 即时行动（Immediate Action）**
- 目标：在下次交互中立即改进
- 特点：具体、可执行、效果立竿见影
- 示例："在不确定时使用'可能'、'根据我的理解'等概率性表达"

**2. 长期改进（Long-term Improvement）**
- 目标：系统性提升认知能力
- 特点：需要持续练习和强化
- 示例："建立事实验证机制，区分已知和推测"

**3. 知识更新（Knowledge Update）**
- 目标：更新认知策略和知识结构
- 特点：涉及认知框架调整
- 示例："学习在不确定场景下的诚实表达策略"

#### 建议生成规则

1. **针对性**：建议必须与具体错误类型和根因相关
2. **可执行性**：建议必须具体、可操作
3. **优先级**：建议按重要性和紧急性排序
4. **避免泛化**：避免使用过于笼统的建议
5. **自我指涉**：建议必须面向智能体自身，而非用户

#### 建议模板

| 错误类型 | 即时行动 | 长期改进 | 知识更新 |
|---------|---------|---------|---------|
| 幻觉倾向 | 明确承认知识边界，使用概率性表达 | 建立事实验证机制 | 学习诚实表达策略 |
| 推理跳跃 | 提供完整推理步骤 | 提升逻辑完整性意识 | 建立隐含假设识别机制 |
| 知识缺失 | 明确说明知识限制 | 建立知识边界识别机制 | 学习诚实表达知识不足 |
| 偏见影响 | 保持中立，平衡多方观点 | 加强偏见敏感度训练 | 更新敏感话题处理策略 |

### 6.7 与五维智力模型的关联

## 8. 时效性管理

### 8.1 三重衰减机制

#### 1. 时间衰减

```python
def time_decay(base_confidence: float, days_since_creation: int) -> float:
    """时间衰减：每日衰减1%"""
    lambda_decay = 0.01
    return base_confidence * math.exp(-lambda_decay * days_since_creation)
```

#### 2. 场景变化衰减

**触发条件**：知识库重大更新、模型版本升级、工具接口变更、领域迁移
**衰减策略**：立即降低置信度 30-50%，需要重新验证

#### 3. 反例衰减

```python
def counterexample_decay(current_confidence: float, counterexample_count: int) -> float:
    """反例衰减：每个反例降低30%"""
    decay_factor = 0.7 ** counterexample_count
    return current_confidence * decay_factor
```

| 状态 | 置信度范围 | 行为 |
|------|-----------|------|
| active | > 0.7 | 正常使用 |
| deprecated | 0.3 - 0.7 | 仅作参考，不自动执行 |
| archived | < 0.3 | 存档，不再使用 |

|---------|---------|---------|------|
| 时间衰减 | 自然过期 | `confidence = base × e^(-0.01×days)` | 每日衰减1% |
| 场景变化衰减 | 知识库更新/模型升级/工具变更 | `confidence × (1-0.35)` | 降低35% |
| 反例衰减 | 预防策略失效 | `confidence × 0.7^n` | 每个反例降低30% |

## 12. 最佳实践

### 12.1 错误记录最佳实践

1. **及时记录**：错误发生时立即记录，避免信息丢失
2. **完整记录**：包含完整的上下文信息
3. **根因深入**：不满足于表面原因，深挖根本原因
4. **预防导向**：记录时就思考如何预防

### 12.2 预防应用最佳实践

1. **优先级排序**：高预防价值规则优先应用
2. **成本控制**：预防成本应低于错误成本
3. **渐进式启用**：新规则先观察，验证后全面启用
4. **用户友好**：预防失败时给出清晰建议

### 12.3 时效性管理最佳实践

1. **定期审计**：定期检查错误知识的有效性
2. **快速响应**：场景变化时及时更新置信度
3. **反馈闭环**：验证结果及时反馈到置信度计算
4. **规则生成**：保持最小聚类规模 ≥ 3，新规则先观察验证

### 12.4 认知性错误预防通用原则

1. **验证先行**：在做出断言前先验证
2. **明确边界**：清晰说明知识的边界和限制
3. **标注置信度**：对不确定内容标注置信度
4. **多角度思考**：避免单一视角导致的偏见
