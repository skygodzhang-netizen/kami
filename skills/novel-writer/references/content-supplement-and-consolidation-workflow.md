# 内容补充与整合工作流 / Content Supplement and Consolidation Workflow

**版本**: v1.0.0  
**适用场景**: 向现有大纲/剧情补充新内容，并进行逻辑检查、修正和文件整合

---

## 工作流程

```
用户请求补充内容
    ↓
识别补充范围和内容类型
    ↓
添加到现有文件
    ↓
【关键】检查逻辑一致性
    ↓
发现问题？
    ├─ 是 → 修正错误 → 记录修正
    └─ 否 → 继续
    ↓
多文件整合需求？
    ├─ 是 → 融合为统一文件 → 精简内容 → 删除旧文件
    └─ 否 → 保持现状
    ↓
更新配置文件引用
    ↓
生成总结报告
```

---

## 阶段详解

### 阶段1: 内容补充

**触发条件**: 用户要求补充新内容（如神话故事、角色、事件等）

**关键步骤**:
1. 读取现有文件，确定补充位置
2. 按格式添加新内容
3. 确保与现有内容格式一致
4. 更新相关时间戳和计数

**示例**:
```python
# 读取现有myth_integration.json
# 在myths对象中添加新神话
# 更新myth_timeline
# 更新protagonist_gains
```

---

### 阶段2: 逻辑检查（关键）

**检查项**:

| 检查类型 | 检查内容 | 常见问题 |
|----------|----------|----------|
| **时间顺序** | 事件发生的先后顺序 | 因果关系颠倒 |
| **角色状态** | 角色在某时间点是否存活/存在 | 已死角色再次出现 |
| **因果关系** | 事件A是否导致事件B | 缺乏因果铺垫 |
| **地理位置** | 场景转换是否合理 | 瞬间移动 |
| **能力边界** | 角色能力是否超限 | 战力崩坏 |
| **物品状态** | 道具是否已获取/使用 | 重复获取 |

**时间顺序检查示例**:
```
错误顺序:
  后羿射日(300-310) → 刑天舞干戚(320-330)
  
问题: 刑天挑战的是帝俊，但后羿射日后帝俊还活着

正确顺序:
  刑天舞干戚(295-305) → 后羿射日(306-316)
```

---

### 阶段3: 问题修正

**发现逻辑错误后的处理流程**:

1. **识别错误类型**
   - 时间顺序错误
   - 因果关系错误
   - 角色状态错误
   - 其他逻辑矛盾

2. **制定修正方案**
   - 调整时间戳
   - 修改事件描述
   - 补充过渡章节
   - 删除冲突内容

3. **执行修正**
   - 更新所有相关文件
   - 保持格式一致
   - 更新交叉引用

4. **记录修正**
   - 创建修正报告
   - 记录修改原因
   - 保留原方案备份

**修正记录模板**:
```markdown
## 修正记录

### 问题描述
[描述发现的逻辑错误]

### 影响范围
[列出受影响的章节/文件]

### 修正方案
[详细描述修正措施]

### 修正结果
[确认修正后的正确状态]
```

---

### 阶段4: 文件整合

**触发条件**: 多个相关文件存在冗余或需要统一

**整合策略**:

| 文件类型 | 整合方式 | 输出格式 |
|----------|----------|----------|
| JSON配置 | 合并为单一JSON | JSON |
| Markdown文档 | 合并为单一Markdown | Markdown |
| 混合类型 | 提取核心内容，转为Markdown | Markdown |

**整合步骤**:

1. **分析文件关系**
   ```
   plot_engine_volume2_overview.json
   plot_engine_volume2_part1.json
   myth_integration_volume2.json
   → 都是第二卷大纲的不同部分
   ```

2. **提取核心内容**
   - 删除重复信息
   - 保留唯一信息
   - 统一格式

3. **创建统一文件**
   - 选择最合适的格式（通常Markdown更易读）
   - 按逻辑结构重组内容
   - 添加目录和交叉引用

4. **删除旧文件**
   - 确认新文件完整
   - 备份（可选）
   - 删除冗余文件

5. **更新引用**
   - 更新配置文件中的文件路径
   - 更新文档中的链接

## 最佳实践

### 1. 补充内容时

- ✅ 保持与现有格式一致
- ✅ 更新所有相关字段（计数、时间戳等）
- ✅ 检查新增内容的唯一性（避免重复）
- ❌ 不要只添加不检查

### 2. 逻辑检查时

- ✅ 按时间线顺序检查
- ✅ 验证因果关系
- ✅ 检查角色状态一致性
- ✅ 考虑连锁反应（修改A会影响B）
- ❌ 不要假设"应该没问题"

### 3. 修正错误时

- ✅ 记录修正原因
- ✅ 更新所有相关文件
- ✅ 验证修正后的完整性
- ❌ 不要只改一处忽略关联处

### 4. 文件整合时

- ✅ 先创建新文件，确认完整后再删旧文件
- ✅ 保留核心信息，删除冗余
- ✅ 选择最易读的格式
- ✅ 更新所有引用
- ❌ 不要直接覆盖，先对比

## 常见错误案例

### 案例1: 时间顺序错误

**场景**: 补充神话故事

**错误**:
```json
{
  "后羿射日": {"timing": "300-310章"},
  "刑天舞干戚": {"timing": "320-330章"}
}
```

**问题**: 刑天挑战帝俊，但后羿射日后帝俊还活着

**修正**:
```json
{
  "刑天舞干戚": {"timing": "295-305章"},
  "后羿射日": {"timing": "306-316章"}
}
```

---

### 案例2: 角色状态错误

**场景**: 角色在A章节死亡，B章节又出现

**修正**: 调整B章节时间，或修改B章节角色

---

### 案例3: 文件冗余

**场景**: 多个版本的配置文件并存

**处理**:
1. 识别最新版本
2. 合并有效内容
3. 创建统一文件
4. 删除旧版本
5. 更新引用

## 工具函数

### 时间顺序检查

```python
def check_chronology(events):
    """
    检查事件时间顺序
    
    Args:
        events: [{"name": str, "start": int, "end": int, "depends_on": [str]}]
    
    Returns:
        list: 发现的逻辑错误
    """
    errors = []
    event_map = {e["name"]: e for e in events}
    
    for event in events:
        if "depends_on" in event:
            for dep in event["depends_on"]:
                if dep in event_map:
                    dep_event = event_map[dep]
                    if event["start"] <= dep_event["end"]:
                        errors.append({
                            "type": "chronology",
                            "event": event["name"],
                            "depends_on": dep,
                            "error": f"{event['name']}({event['start']}-{event['end']}) "
                                    f"应在 {dep}({dep_event['start']}-{dep_event['end']}) 之后"
                        })
    
    return errors
```

### 文件整合

```python
def consolidate_files(files, output_path, format='markdown'):
    """
    整合多个文件为单一文件
    
    Args:
        files: [Path] 待整合文件列表
        output_path: Path 输出文件路径
        format: str 输出格式 ('markdown'|'json')
    """
    if format == 'markdown':
        content = []
        for f in files:
            content.append(f"## {f.stem}\n")
            content.append(f.read_text())
            content.append("\n---\n")
        output_path.write_text("\n".join(content))
    elif format == 'json':
        merged = {}
        for f in files:
            data = json.loads(f.read_text())
            merged.update(data)
        output_path.write_text(json.dumps(merged, indent=2))
```

## 总结

内容补充与整合工作流的核心是：**先补充，再检查，后修正，最后整合**。

关键要点:
1. **逻辑检查不可少** - 补充内容后必须检查一致性
2. **发现问题及时修正** - 不要累积错误
3. **整合时保留核心** - 删除冗余，保留精华
4. **更新所有引用** - 避免断链
